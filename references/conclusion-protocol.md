# Conclusion 写作流程

本文件仅用于 Conclusion 模式；摘要不套用本文件的候选确认流程或 3–4 条目标。

先通读全文并提取信息，向作者提交候选结论，确认后再按“具体问题 → 简要方法 → 核心判断及必要证据 → 综合贡献 → 可选的局限与后续方案”写作。核心结论以 3–4 条为目标，重点交代研究最终支持哪些认识，并与 Introduction 提出的问题对应。默认沿用原稿语言，尊重用户指定的长度、结构及期刊要求。

## 必须先通读全文，再提取信息

起草、实质改写或评估整篇论文的 Conclusion 前，先读取用户指定的当前完整稿件。原 Conclusion 是待检查的总结，不能替代正文证据。

1. **确认全文与版本。** 从用户提供的文件、附件或可访问的稿件中定位当前版本。已有全文就直接读取，不要求用户重新粘贴；不以同名旧稿替代当前稿。
2. **通读全文。** 完整阅读 Abstract、Introduction、Methods、Results、Discussion 和现有 Conclusion，检查图、表、图注及支撑核心判断的补充材料。记录实际覆盖的章节；长文分段读取，补齐被工具截断的内容，不把关键词检索、摘要或若干命中片段当作通读完成。结构不同的论文按其实际章节阅读。涉及图表的结论须检查实际图表内容，不能只依赖图注。
3. **建立全文信息提取表。** 在写 Conclusion 前，从正文提取下表信息，并记录章节、页码、段落、图号或表号等可回查位置。只使用实际存在的定位信息，不编造页码。区分原始结果、作者解释和未来设想。

| 提取对象 | 需要记录的信息 |
| --- | --- |
| 研究问题 | Introduction 提出的具体缺口、目标，以及本文实际回应到什么程度。 |
| 核心方法 | 对象、数据、核心思路，以及影响结论可信度的验证设计和比较对象。 |
| 关键发现 | 各主要分析支持的判断、必要数值与条件、对应图表，以及会改变判断的例外。 |
| 综合贡献 | 多项发现共同增加了什么认识或能力，正文中的支撑位置。 |
| 局限与后续方案 | 实际限制、影响哪些结论、对应验证或改进方案，以及 Discussion 是否已经充分讨论。 |

4. **核对后提交作者确认。** 将原 Conclusion 的每项实质主张与提取表核对，再提出保留、压缩、补充或改正建议。数字、比较对象或结论在不同章节不一致时，先回查来源；未能解决的冲突须具体指出，不能自行择取有利版本。从全文挑选真正重要的发现，不把原 Conclusion 中已有的信息视为全部候选内容。

**材料不足时：** 仅有摘要、原 Conclusion 或部分结果时，说明尚未通读全文，并请求完整稿件或缺失章节；可先交付已有材料的提取表并标明缺口，不交付声称代表全文的最终结论。若用户明确限定为局部语言润色或明确要求先做片段草稿，则按该范围执行，并简短说明依据范围，不声称已完成全文核查。无法读取的图表或补充材料也应具体列明，不能默认为已检查。

## 候选结论：先总结、排序，再由作者确认

**3–4 条指核心研究判断的数量。** 问题定位、方法概述、综合收束句及局限段不计入条数。连续段落写法也遵守这个核心数量目标，不以句子数或段落数代替结论数。证据不足以形成三条独立结论时，向作者说明，不能拆分重复判断或虚构发现来凑数。

全文读完后先交付研究问题、方法、贡献和局限的简明提取摘要，并将全部有依据的独立候选结论列入下表。给候选分配稳定编号 C01、C02 等，每项写成完整的方向性判断，附证据位置与必要适用条件。

| 候选编号 | 核心判断 | 正文证据与条件 | 优先级及理由 | 建议保留或合并 | 作者决定 |
| --- | --- | --- | --- | --- | --- |

- **候选不超过 4 条：** 提出建议的 3–4 条组合，交由作者确认核心判断及措辞；不足三条时如实报告并请作者判断重点，不强行补齐。
- **候选超过 4 条：** 展示全部候选，按“对研究问题的回应程度、证据充分性、贡献重要性、与其他候选的独立性”排序并说明理由。保留原编号，用单独的优先级列表示次序。提出 1–2 套压缩到 3–4 条的方案，明确哪些保留、哪些合并、哪些建议舍去及原因，供作者选择；不能在展示前自行删到四条。结果数值多或模型分数高不自动代表优先级高。
- 合并围绕同一问题且相互支持的判断，说明合并后的表述及来源编号，如“C02 + C05 → 一项结论”。保留影响该判断的反例和适用条件，不能为压缩条数隐去相反结果。
- **提交后停在确认阶段。** 明确请作者选择保留、合并或删除的编号，或确认推荐组合。此时不同时给出完整 Conclusion，作者未回复不等于确认。
- 作者确认后，以确认的 3–4 条为骨架写正文。已有确认可直接沿用，不反复询问；如新增、删除或实质改变核心判断，先提交变更供确认。仅要求“只输出结论正文”或设定字数不代表已确认候选；用户明确要求跳过确认、直接写作时按其指示执行。

## 写作顺序

1. **第一句点明本研究回应的具体问题。** 可以在同一句交代研究回应，但问题必须可辨认。写出具体缺口，如“性能损失与恢复过程缺少统一刻画”，避免用领域重要性、宏观背景或单独的“本文提出了某方法”开场。按完成程度选择“解决、明确、刻画、提供依据”等措辞。

2. **用 2–3 句概述方法。** 说明核心思路、研究对象或数据，以及验证或比较方式，以理解贡献所需为限。方法简单或篇幅紧时可压缩为一句；方法本身是主要贡献时可充分交代。只写实际做过的工作，无需复述步骤、参数和全部实验设置。

3. **将实验或分析发现提炼为有方向、有条件的判断。** 围绕什么更关键、哪些关系得到支持、效果随什么条件改变，以及这些发现意味着什么来写。把相关实验归并为结论，避免按照实验顺序逐项汇报。“倾向性”表示证据支持的方向，不是择取有利结果。保留会改变核心判断的反例和差异，不把相关性写成因果，也不把排序差异解释成未经证实的完整机制。

4. **用一句综合贡献收束主要发现。** 说明几项发现合起来推进了什么认识、使什么问题能够被评估，或支持什么具体实践。贡献必须可追溯到正文；“建立框架、开展实验”本身还没有说明新增认识。避免“意义重大、提供全新视角”等可替换到任意论文的评价。

5. **按需要补充局限与后续方案。** 如果 Discussion 已充分讨论，或论文整体较长且无需在此补充新的必要说明，可以省略独立局限段。若某个条件直接决定核心结论是否成立，将它简短保留在对应判断中。需要写局限段时，可用简短过渡引出实际限制，并为每项限制匹配后续验证、数据补充或方法改进。未来方案使用未来时态；不添加材料未支持的通用缺点或机械的未来工作清单。

## 数值与分点的选择

| 情况 | 写法 |
| --- | --- |
| 优化模型或以 performance 为核心的论文 | 保留关键指标、比较对象和必要提升幅度，交代实际测试条件。 |
| 以规律、机制、框架或应用认识为核心的论文 | 以方向性判断为主，只保留决定结论的数值，如关键阈值、效应幅度或转折点。 |
| 多个实验回答同一个问题 | 合并为一项发现，避免罗列各组分数或重复精度。 |
| 多项独立发现、关系较复杂 | 可按结论分点，每点包含一个完整判断及其含义；末尾用综合贡献汇合。 |
| 内容简短、逻辑连续 | 可将作者确认的 3–4 条判断组织为连贯段落，无需强行编号。 |

保留的数值、单位、比较方向及不确定性须与来源一致。“差异不显著”不能直接改成“等效”；有限实验不能支撑普遍优越性。只有计划或框架、没有实验的论文，围绕其实际分析与贡献写作，不虚构验证。

## 示例

以下为虚构示例，仅示范表达方式；实际使用须有相应证据。

结果复述：“不同特征组合的准确率分别为……，完整特征集的准确率为……。”

结论提炼：“在所测试的低标注条件下，识别性能主要取决于少量关键声学特征，继续扩充特征集带来的收益有限。这支持在标注资源受限时优先筛选关键特征。”

## 交付与检查

- **第一阶段：全文总结与候选确认。** 给出全文信息提取摘要和候选结论表；超过四条时附排序与合并方案，然后等待作者决定。提供的表述是候选主张，不是已经定稿的 Conclusion。
- **第二阶段：依据确认结果写作。** 作者确认后再交付 Conclusion 正文，以确认的 3–4 条为核心；控制字数时压缩措辞，不擅自增删核心判断。用户只要正文时不重复提取表。不额外改写 Discussion 或无关章节；文件编辑仅覆盖用户授权范围。
- **仅评估请求：** 给出整体判断及具体句子的“问题 → 建议”，不擅自把建议当作已保存的修改。
- 交付前确认：全文阅读覆盖完整、提取内容可回查；候选已交作者确认，核心判断数量符合确认结果；首句问题明确；方法简洁；主要发现形成判断；必要数值准确；综合贡献有依据；局限段取舍合理且方案对应；没有新添未经支持的发现、机制、验证或泛化。
